# Как объяснить лабораторную на защите

## Короткий рассказ

Я сделал программу, которая считает площадь и периметр четырёх фигур.
Для каждой фигуры есть отдельный модуль и две функции: `area` и `perimeter`.
Я заранее выбрал входные данные и посчитал ожидаемые ответы.
Потом написал 51 тест с помощью стандартного модуля `unittest`.
Тесты проверяют обычные значения, границы допустимых данных и ошибки.
Все тесты проходят. На временно испорченной формуле периметра тест нашёл ошибку.

## Что происходит в одном тесте

```python
class RectangleTestCase(unittest.TestCase):
    def test_area(self):
        self.assertEqual(rectangle.area(3, 4), 12)
```

1. `class` создаёт класс, в котором собраны тесты прямоугольника.
2. Наследование от `unittest.TestCase` даёт методы проверки результатов.
3. Имя начинается с `test`, поэтому unittest найдёт этот метод.
4. `rectangle.area(3, 4)` вызывает настоящий код программы.
5. `assertEqual` сравнивает результат с заранее известным числом 12.
6. Если результат отличается, тест завершается с `FAIL`.

## Основные вопросы

**Что такое unit-тест?** Проверка отдельной небольшой части программы,
например одной функции, без запуска всей программы.

**Зачем автоматизация?** Можно одной командой повторить все проверки после
изменения кода. Не нужно каждый раз вводить размеры вручную.

**Почему ожидаемый результат записан числом?** Он рассчитан независимо от
проверяемой функции. Если получить ожидание вызовом самой функции, тест не
сможет обнаружить её ошибку.

**Чем отличаются проверки?** `assertEqual` проверяет точное равенство;
`assertAlmostEqual` — приблизительное равенство вещественных чисел;
`assertRaises` — возникновение определённого исключения;
`assertIsNone` — что функция проверки успешно вернула `None`.

**Почему дробные числа сравниваются приблизительно?** Числа вроде 0.1
не представляются в двоичной системе абсолютно точно. Небольшая погрешность
сама по себе не означает ошибку формулы.

**Что такое граничный случай?** Значение на границе разрешённого диапазона:
например 0 или 1 000 000 000. Проверяется и значение сразу за верхней границей.

**Почему ноль разрешён?** Для прямоугольника, квадрата и круга он нужен как
граничный случай, аналогично примеру из задания. Для треугольника с тремя
сторонами принят другой контракт: все стороны положительны, фигура невырожденная.

**Зачем ограничение 1 000 000 000?** Это выбранное требование учебного продукта:
оно задаёт явную верхнюю границу и позволяет проверить её и выход за неё.
Это не требование из методички.

**Чем отличаются TypeError и ValueError?** TypeError: передали не тот тип,
например строку вместо числа. ValueError: тип правильный, но значение
недопустимо, например отрицательная длина.

**Что такое subTest?** Несколько наборов данных внутри одного тестового метода.
При ошибке видно, какой именно набор не прошёл. Поэтому наборов данных больше,
чем 51, но unittest считает 51 метод.

**Чем FAIL отличается от ERROR?** FAIL означает, что проверка assert не
выполнилась. ERROR — при выполнении теста возникло неожиданное исключение.
Ожидаемое исключение внутри assertRaises считается успешной проверкой.

**Почему unit-тесты независимы?** Они напрямую вызывают функции, не используют
сеть, файлы, пользовательский ввод и общее изменяемое состояние.

**Доказывает ли OK отсутствие всех ошибок?** Нет. OK означает, что пройдены
выбранные проверки. Исчерпывающая проверка всех чисел и всех ошибок не выполнена.

## Команды для демонстрации

```bash
python3 main.py rectangle 3 4
python3 main.py triangle 1 2 3
python3 -m unittest discover -s tests -v
python3 -m unittest tests.test_rectangle.RectangleTestCase.test_perimeter -v
git log --oneline
```

При `triangle 1 2 3` ожидается сообщение об ошибке: такой невырожденный
треугольник не существует. Это корректная работа программы.

Пример обнаруженного дефекта сохранён в `docs/failure_demo.txt`.
Формула изменялась только во временной копии: `a + b` вместо `2 * (a + b)`.
Тест получил 7, ожидал 14 и завершился с FAIL.
